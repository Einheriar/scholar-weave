# 待讨论：文档、对话与「历史记录」的概念边界

> 状态：**待讨论**，未定方案。本文只记录分歧点与候选方向，不驱动实现。
> 提出日期：2026-09-16
> 相关：[`../AGENTS.md`](../AGENTS.md)「左侧对话历史」一节、[./PLAN.md](./PLAN.md)

## 背景：用户预期与当前设计的分歧

用户反馈（2026-09-16）：粘贴文字进正文后「历史记录没有更新」；点「新对话」后「原来的文字没被删掉」。

排查结论：**这不是 bug，是概念模型的分歧。** 当前应用里有两个彼此独立的东西：

| | 正文文档（中间编辑区） | 对话（底部输入框 + 左侧历史） |
|---|---|---|
| 本质 | 被审阅的文章 | 围绕文章与 AI 的问答 |
| 持久化 | `documents` 表（草稿） | `conversations` 表（历史） |
| 何时进「历史记录」 | **从不** | 点「发送」发消息才进 |
| 「开始审阅」按钮 | 分析它 → 产出侧栏建议卡片 | 与历史无关 |
| 「新对话」按钮 | **不清它** | 只清对话界面 |

用户的直觉模型是「一次完整的工作（粘文章 → 审阅 → 改）应该作为一个可回看的单元」，而当前实现里「历史记录」只装**对话**，不装**审阅行为**也不装**文档版本**。两边对「历史」一词的所指不同。

## 已确认的事实（实测）

- 发消息 → IndexedDB `conversations` 立刻写入、左侧列表立刻出现、LLM 回复后更新轮次、刷新后保留。**对话留痕机制正常**。
- 「新对话」`handleNewConversation` 明确 `setChatTurns([])` 清对话轮次，**不碰正文**——这是 AGENTS.md 写明的设计（「只清对话界面，正文不受影响」）。
- 「开始审阅」走 `/api/review` 产出建议卡片，**从不写对话历史**——审阅与对话是两条独立链路。

## 候选方向（未选定）

用户预期可能对应以下一种或多种，**需与用户确认后再设计**：

- **(甲) 审阅行为进历史**：把「对《某文档》做了一次某模式审阅」作为一类历史条目，可回看历次审阅结果。这要求历史从「纯对话」扩成「对话 + 审阅事件」的时间线。
- **(乙) 一键「全新开始」**：一个操作同时清空正文 + 清空对话 + 清空建议，重置整个工作台。区别于现在的「新对话」（只清对话）。
- **(丙) 概念合并**：把「文档 + 它的审阅 + 它的对话」打包成一个「工作区 / 会话」单元，历史按工作区组织而非按对话组织。这是最贴近用户直觉、但改动最大的方向。

## 待回答的问题

1. 用户说「历史记录应该有」，指的是「我跟 AI 说过的话」（已有）还是「我做过哪些审阅 / 处理过哪些文章」（没有）？
2. 「新对话」不符合预期，是因为它该清正文（→ 方向乙），还是因为历史该按「文章」组织（→ 方向丙）？
3. 若做 (甲) 或 (丙)，`conversations` 表结构、`ChatHistory` 左侧栏、「清空数据」都要跟着改，工作量与 PLAN 第 18 节的演进方向如何对齐？
