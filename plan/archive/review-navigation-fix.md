# 审阅建议双向定位修复

日期：2026-10-10。状态：已完成。

## 问题与目标

现有正文→建议定位会将卡片对齐到原文；建议→正文仅调用编辑器默认滚动，不考虑底部聊天浮层，也不保证原文与卡片处于可对照的高度。

点击局部／段落建议后，正文应主动滚到聊天浮层上方的可读区域，尽量与被点击卡片的中心对齐。若卡片中心位于可读区域之外，将正文目标位置限制在可读区域内，再按正文最终位置调整卡片。正文与卡片完整可见优先于严格对齐；全文建议继续定位全文总结。

## 实现边界

1. 继续使用本地锚点解析，不猜测失效或歧义位置；只选中已成功定位的原文，保持 review 聊天上下文。
2. 建议定位禁用编辑器默认焦点滚动，按整个 `data-editor-dock` 的上边缘计算正文可读区域。
3. 优先以被点击卡片的中心作为正文目标高度；窄屏侧栏在正文下方时使用正文可读区域的默认位置。
4. 正文滚动完成后，将实际原文高度传回既有侧栏对齐逻辑。重复点击仍能重新定位；连续点击取消旧滚动，避免旧回调覆盖新选择。
5. 真人保留短距离平滑滚动；减少动态效果与 E2E 使用即时定位。用户主动滚动／操作时取消尚未完成的自动滚动。
6. 不修改正文、协议、保存状态或接受／撤销行为。保留当前未提交的聊天报错改动。

## 验证

- E2E：长文中点击建议后，原文进入可读区域；聊天展开／收起时都不被遮挡；同一建议重复点击与连续切换可以重新定位；人工选区后仍维持 review 上下文。
- 保留正文→侧栏定位、全文建议与无法定位建议的行为。
- 运行编辑器集成测试 `tests/editor-batch-apply.test.tsx`、相关 E2E、类型检查、lint 与 `git diff --check`。

## 执行记录

- 已确认根因：`DocumentEditor.revealItem` 使用 `.focus().setTextSelection().scrollIntoView()`，未考虑底部浮层；`handleSelect` 清空正文对齐坐标，未在滚动完成后回传实际位置。
- 已改为关闭默认焦点滚动、自管可取消的正文滚动，并在完成后复用侧栏的实际位置对齐；侧栏保底定位只滚内部容器，避免与正文滚动互相干扰。
- 真人平滑滚动最长 500ms；减少动态效果与 E2E 使用即时定位。输入、编辑及连续定位取消旧正文动画，侧栏用户输入也取消尚未完成的卡片动画。
- 验证通过：编辑器集成 13 项、hardBreak 坐标 4 项、既有核心 E2E 15 项、新增定位 E2E 3 项（含真人平滑滚动分支）、类型检查、目标文件 lint、`git diff --check`。
- 永久约定已同步写入 `AGENTS.md`；本方案完成后归入 `plan/archive/`。提交对应记录见 `plan/CHANGELOG.md`。
